# Task 1：上下文工程

## 这次做了什么

我按教材跑了 Chapter 2 的 context-compression 实验，选的是 context_aware 策略。模型配置是 kimi-k3，搜索使用 Serper。命令如下：

    ../../.venv/bin/python experiment.py -s context_aware

这次运行成功，花了约 641 秒，过程中有 7 轮、15 次工具调用，共记录 35,596 tokens，没有发生上下文溢出。实验显示，输入材料有 1,117,822 个字符，压缩后是 29,729 个字符，约为原来的 2.7%。这个比例看起来很直观，但它只能说明文本变短了，不能单凭数字说明重要信息都保住了。

## 我的理解

以前我会觉得 Prompt 和 Context 差不多，都是“给模型看的内容”。现在我理解，Prompt 更像是其中的指令；Context 范围更大，还可能带着之前的对话、工具说明、搜索结果和任务做到哪一步。模型能一次处理多少内容也有限，塞进去的东西太多，可能超出窗口；即使没超，真正重要的要求也可能被一大堆材料盖住。

这次实验让我比较有感觉的是“压缩不等于删短就好”。如果摘要把任务条件、搜索依据或还没解决的问题丢了，后面的回答仍然可能出错。做 Agent 时，应该只把当前需要的信息交给模型；要压缩历史时，也得留下关键要求和依据。实验跑了十多分钟，最后看到材料缩到很小，确实能感受到压缩的效果，不过我这次只跑了 context_aware 这一种策略，还不能比较哪种策略最好，也还需要检查摘要保留的信息是否足够。
