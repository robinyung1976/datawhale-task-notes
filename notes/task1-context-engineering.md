## 学习理解（100 字以上）

Prompt 通常是交给模型的一条或一组指令，而 Context 是模型当前这次决策实际能看到的完整信息状态，可能包括系统与用户消息、历史对话、工具定义、工具调用结果、检索材料以及任务状态。Context Window 是模型一次处理输入和生成输出的 token 容量边界；内容过多会带来成本、延迟或溢出，即使没有溢出，关键约束被大量材料淹没也会让模型更难找到它们。上下文工程因此不只是“把提示词写好”，还要决定哪些信息进入上下文、如何排序和标注来源、何时检索或压缩，以及哪些目标、事实、引用和未解决问题必须保留。本次 context-aware 实验让我看到，压缩可以显著缩短材料，但摘要质量和任务相关性同样重要：压得短不等于保留得好，必须结合最终任务检查遗漏与依据。实际 Agent 应尽量按需加载信息，并在压缩时保留约束、证据、来源和行动状态，从而在有限窗口内维持可靠性。
